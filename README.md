# Волновой зомби-шутер — прототип (Roblox)

Игровой прототип по дизайн-документу «Волновой зомби-шутер» (v0.1, черновик).
Реализует основной игровой цикл: лобби → выбор сложности → отражение волн
зомби → закупка оружия и патронов → следующая волна → победа/поражение →
возврат в лобби.

## Как запустить

Проект — обычный [Rojo](https://rojo.space/)-проект, весь код в `src/`,
никаких внешних ассетов не требуется (уровень, оружие и зомби строятся
скриптами прямо в `Workspace` при старте сервера).

1. Установите Rojo (CLI + плагин для Roblox Studio).
2. В корне репозитория выполните `rojo serve`.
3. В Roblox Studio откройте пустое место (baseplate) и подключитесь плагином
   Rojo к `rojo serve`.
4. Запустите тест минимум с двумя симулированными игроками
   (Test → Start Server, добавить пару клиентов), чтобы проверить кооператив.

## Структура

- `src/ReplicatedStorage/Modules/GameConfig.lua` — все табличные данные:
  сложности, оружие, типы зомби, состав волн (разделы 6, 8, 9 документа).
- `src/ReplicatedStorage/Modules/Remotes.lua` — реестр RemoteEvent.
- `src/ServerScriptService/Server/` — вся серверная логика:
  - `MapBuilder.lua` — процедурная блокаут-геометрия лобби и арены.
  - `ZombieFactory.lua` / `ZombieAI.lua` / `ZombieSpawner.lua` — модели
    зомби, ИИ преследования/атаки, волновой спавн.
  - `WeaponFactory.lua` / `WeaponServer.lua` — инструменты оружия,
    серверная валидация выстрелов (весь урон считается на сервере).
  - `ShopService.lua` — точки закупки оружия и патронов.
  - `PlayerDataService.lua` — метапрогрессия через DataStore.
  - `GameManager.lua` — состояние сессии (лобби/волна/торговое окно/финал).
- `src/StarterPlayerScripts/` — клиент: HUD и управление оружием (весь
  интерфейс строится кодом через `Instance.new`). Выбор сложности — это
  физические порталы в лобби (см. MapBuilder.lua), не экранные кнопки.

## Реализованные механики (соответствие документу)

- Игровой цикл разделы 3, 6, 7: 8 волн, торговое окно 25 сек между ними,
  усиленная финальная волна с элитными противниками.
- 7 типов зомби из раздела 8: обычный, ползающий, плюющийся кислотой,
  огненный, бегающий, прыгающий, плюс элитный/танковый тип (рекомендация
  раздела 8 для финальной волны).
- Экономика оружия и патронов (раздел 9): стартовый пистолет с бесконечным
  боезапасом, дробовик/автомат/снайперка на точках закупки с ростом цены и
  урона по категориям, бесплатные пункты пополнения патронов на карте.
- Сложность (раздел 6): 4 уровня с точными множителями здоровья/урона
  зомби, количества и валюты/опыта из таблицы документа. Выбирается через
  4 портала в лобби (по одному на уровень сложности) с плавающей надписью
  над каждым — название и точные множители, подтягиваются из GameConfig.
  Заход в портал сразу запускает сессию на этой сложности.
- Метапрогрессия (раздел 10): персистентная валюта аккаунта и уровень
  через DataStore, отдельно от внутрисессионной валюты.
- Серверная авторитетность (раздел 13): весь урон, спавн и экономика
  считаются на сервере, клиент только сообщает точку прицеливания.

## Осознанные упрощения прототипа

Документ сам оставляет часть решений открытыми (раздел 14) — для прототипа
были приняты конкретные варианты, чтобы получить играбельный билд:

- **Один сервер = одна сессия.** Нет паблик/приватных лобби, голосования,
  TeleportService и Reserved Servers (раздел 4) — все игроки на сервере
  автоматически считаются одной командой.
- **Одна карта, без модификатора дня/ночи** (раздел 5) — только один
  блокаут-уровень без тематических вариаций.
- **Смерть игрока необратима до конца сессии** — один из трёх вариантов,
  прямо оставленных открытым вопросом №2 в разделе 14. Другие варианты
  (полный респавн, даун-стейт с реанимацией) не реализованы.
- **Прыгающий зомби** упрощён до периодического рывка в сторону цели —
  полноценная непредсказуемая траектория не реализована.
- **Переносной ящик патронов за Robux** (раздел 9/11) не реализован —
  требует MarketplaceService и опубликованной игры с настроенными
  Developer Products, вне рамок офлайн-прототипа.
- Визуальные трассеры выстрелов рисуются только локально у стрелка —
  другие игроки их не видят (чисто косметическое упрощение, на урон и
  экономику не влияет).
- ИИ передвижения зомби — прямой `Humanoid:MoveTo()` к ближайшей цели без
  pathfinding (арена открытая, специально спроектирована без сложных
  препятствий).

Все числовые значения (сложность, цены, урон, здоровье) — черновые, как и
в самом документе, и требуют калибровки на плейтестах.
